This is my resume, presented as an observability platform. Each monitoring idea maps to a part of my career:

Time range
My career timeline, on the Career Overview dashboard.
Logs
Achievements from each job, as log lines in Explore.
Traces
Projects, with their phases as spans, in Traces.
Service map
How technologies, projects and jobs connect, on the Service map.
Plain resume
A classic one-page resume, in the Plain view.

Nothing on these pages is written into the frontend. The content lives in a PostgreSQL database and is served by a NestJS API. The panels (stats, timeline, logs, traces, service map) are calculated on the server from that data by a shared, unit-tested library, resume-metrics. A few of its rules are reused in the browser: the timeline's month arithmetic and the span-outline rules of the admin form.

Every panel on the site has Inspect data in its menu (⋮): it shows the raw JSON the API returned for it.

The site has one owner account. I sign in with a JWT session; the password is hashed with bcrypt, salted, and peppered with a server-side secret (HMAC-SHA256).

The API is secure by default: a global guard protects every route, and only the public read routes and the login are marked public.

From the admin area I create, edit and reorder all the content: profile, experience and its highlights, skills, education, and projects with their span outline. Visitors are read-only; the Sign in link in the sidebar is for the owner. An edit there changes what every dashboard shows on the next load.

  • Nx monorepo: Angular 22 (standalone, zoneless, signals), NestJS 11 with TypeORM, PostgreSQL 16.
  • Shared libraries: @my-resume/api-models (API types used by both apps), @my-resume/resume-metrics (dashboard, logs, traces and service-map calculations), @my-resume/query-parser (Explore's LogQL-style queries).
  • Docker images built by GitHub Actions and published to GHCR. nginx serves the frontend and forwards /api to the backend.
  • Hosted on Render's web services.

Why Nx
One repository with a shared, typed API contract: changing the API breaks the build on both sides instead of failing at runtime. Locally, nx affected checks only what a change touches; CI checks every project.
Why ECharts, with our own small wrapper
Only the chart types in use are imported, and they load lazily on the pages that need them (no ngx-echarts). Stats, logs and the trace waterfall are plain HTML/CSS: lighter and more accessible.
Why re2js
Visitors' Explore queries run on the server, so their regexes run in linear time: no ReDoS.
Why the calculations are in a shared library
They are pure functions, unit-tested with hand-checkable fixtures, and the admin form uses the same span-outline rules as the trace view.
